# 项目简介

## 项目名称与定位

船舶装备故障诊断智能问答系统，面向发动机、液压系统、电气设备的维修与运维知识查询。系统把维修手册和故障案例组织为文本索引与知识图谱，通过网页和微信小程序提供带引用的问答，并集成图片辅助诊断和海上天气。

本说明依据 2026-11-02 的仓库实现。详细启动方式和代码默认参数见 [README.md](README.md)。

## 已实现功能

- 双端交互：React 网页端和原生微信小程序共用 FastAPI 后端，支持登录、设置和聊天记录管理。
- 混合检索：ChromaDB 向量召回与 BM25 关键词召回，结合查询改写、问题分解、父子检索、领域路由和交叉编码器重排序。
- 图谱增强：Neo4j 关联设备、故障及处理知识，结合文档映射补充回答上下文和图谱展示。
- 流式问答：SSE 返回阶段进度、答案片段、参考文献及三元组；默认在线模型为 ModelScope 的 `Qwen/Qwen3.5-27B`。
- 图片辅助诊断：先由视觉模型描述设备图片，再经用户编辑确认后进入常规 RAG 诊断，支持主备视觉模型切换。
- 知识更新：支持上传 TXT、Markdown、PDF 并增量更新共享索引；支持按发动机、液压、电气等子图构建和合并发布知识图谱。
- 设备业务数据：独立 SQLite 保存设备台账、参数、检修、报警与故障记录；支持 CSV 管理及自然语言转只读 SQL，查询结果附表格与 SQL 依据。
- 海上天气：合并气象和海洋预报、地点搜索与位置反查，将逐日天气存入 SQLite，并按年月查询和尝试回补历史数据。

## 技术组成

| 层次 | 当前技术 |
|---|---|
| 网页端 | React 19、Vite 8、Tailwind CSS 4、ECharts 图谱展示 |
| 微信小程序 | 原生 JavaScript、WXML、WXSS，分块接收流式响应 |
| API | Python、FastAPI、LangServe |
| RAG | LangChain、ChromaDB、Sentence-Transformers、BM25、Transformers |
| 知识图谱 | Neo4j、LangGraph 七步构建流水线 |
| 模型 | 默认 ModelScope；后端可配置 Ollama；可关闭生成使用抽取式回答 |
| 业务存储 | SQLite、SQLAlchemy，另有生成上下文的 JSON 会话历史 |
| 辅助工具 | CLI、Streamlit、SSE 联调和 RAGAS 评测脚本 |

## 处理流程

1. 文档清洗、切块、向量索引构建；按需抽取、合并并发布知识图谱。
2. 用户输入问题，或上传图片生成描述后提交问题。
3. 查询改写与分解，利用父文档、领域信息、向量和 BM25 召回候选。
4. 重排序并补充相邻片段、知识图谱关系及关联文档。
5. 生成回答或返回抽取式结果，通过 SSE 展示进度、答案和引用。
6. 将聊天、设置与天气数据按对应模块持久化。

## 运行模式与边界

默认问答、视觉识别和天气依赖联网。后端配置 `RAG_LLM_PROVIDER=ollama` 并准备本地模型后，可使用本地生成。网页与小程序的“离线模式”实际上发送 `use_llm=false`，使用抽取式回答，不会自动切换到 Ollama；若要避免问题分解发起在线请求，还需将分解方法设为 `heuristic` 或关闭分解，并提前准备嵌入模型和索引。

当前账号登录未建立服务端 token/会话鉴权，设备业务写接口单独校验管理员身份，原有按用户标识保存数据不等于访问隔离；上传追加到共享知识库。部署前还需核对前端依赖清单、API 地址和模型缓存，具体限制见主 README。

准确率、响应耗时及内存占用需要在指定模型、硬件和数据集下实测。早期设想的 Top1 ≥ 75%、单轮 ≤ 3 秒、内存 ≤ 8GB 属于设计目标，仓库现有材料不足以认定为已达成指标。
